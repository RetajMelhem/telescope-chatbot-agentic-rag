# Bounded referent-context comparison

The authorized development experiment compares the opt-in v8 `purpose_contract`
control with v9 `referent_context`: 48 frozen English, Arabic and Jordanian Arabic
requests, one planning attempt per arm, 96 maximum. These are exposed development
contrasts, not a held-out generalization estimate. No default graph adoption follows
from this experiment.

Run `python -m scripts.run_referent_comparison --output <new-artifact-directory>`
to prepare; the same command with `--execute` authenticates the saved plan,
preparation seal, source inputs and complete payload inventory before dispatch.
Execution requires committed code and an exclusive start receipt. A failed or
ambiguous attempt is never retried. Output is capped at 4,096 tokens per attempt,
with the unchanged normal reasoning, model, schema and 30-second provider timeout.

Only the appended referent instruction and user prompt-version tag differ between
arms. Both receive identical source metadata, purpose definitions, source authority,
requests and literal validation. Gold criteria and witnesses never enter model input.
Schema/literal checks do not judge meaning: each actual plan and its parts require
individual language review against the frozen criteria and saved official sources.
Missing or truncated plans remain unassessable. Report regressions, shared failures
and review limitations alongside gains; do not infer answer/retrieval accuracy.

The project dotenv key is used without exposing or rewriting it. Read-only key
allowance and current pricing observations inform the experiment estimate; normal
chat still uses provider-reported usage without a local input-token guard. An
estimate is not an invoice or guaranteed input bound. Report actual usage and any
billing lag explicitly. There are no draft, embedding, Qdrant, reserved-case,
deployment or paid judge calls in this experiment.
