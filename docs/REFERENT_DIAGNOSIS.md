# Offline referent and source-context diagnosis

The saved v8/v9 comparison remains unadopted. A new diagnostic runner replays its
96 actual outputs exactly and exercises unchanged consumer nodes with explicit
local candidate/draft fixtures. It makes no provider, embedding, ranking or index
request. Fixtures establish conditional consumer behavior, not how Luna would
answer or which sources dense retrieval would rank.

The main run contains 58 probes: 44 with unchanged actual plans and 14 explicitly
authored alternatives. All 14 previously withheld plans have original-plan probes.
Four supplementary probes test draft state and cross-part citation boundaries.
Primary language reasoning individually reviewed all 62 fixture outcomes against
12 whole saved Telescope chunks; scripts verified 65 original DOM references,
coverage and receipt equality. This is not another exhaustive corpus audit or
independent second semantic review.

| Finding | Established effect | Important limit |
| --- | --- | --- |
| Missing service/group antecedent | Exact deficient query reaches retrieval unchanged; full original question still reaches draft input. | Changed rankings and real Luna answers were not measured. |
| Lost governing source context | Profile-scoped training filters out existing main-directory training cards, even when those cards support the role sibling. A source-only authored alternative restores both distinct owners. | Hidden reasons for the model's page selection remain unknown. |
| Name-only profile | Its doctor card remains context-only for biography/training. | Unrestricted profile sections can still offer irrelevant contact footer quotes. |
| Genuine singular ambiguity | A wrongly public plan can admit both doctors' cards; an explicit clarification alternative performs no retrieval. | Draft validation cannot reclassify a supported public part as clarification. |
| Missing comma | Existing whole-request coverage refuses before dependencies; a literal authored comma alternative preserves public and excluded parts. | No coverage rule was relaxed. |
| Authentic but irrelevant quote | Other service methods, contact footers or a prohibited neighboring service can pass exact quote checks in deliberately adverse fixtures. | Quote authenticity, source ownership and scope membership do not prove relevance or entailment. |

Source text is not missing in the inspected training cases. The main directory
publishes distinct training claims; the standalone profiles publish names only.
Do not repair the plan by inventing biographies, borrowing sibling permissions,
merging doctors, expanding arbitrary source access or deleting useful contact
content. Exact footer coalescing preserves both native occurrences; it does not
give an ownerless contact block a doctor's biography ownership.

The planner-visible entries for the sparse profiles currently expose their titles,
doctor/section types, English language and `source_role=unclassified`, without
the owned cards' name-only limitation. The purpose contract describes that
limitation generically. This is an observed information gap, not proof that it
caused a particular choice. Source metadata alone would still not resolve an
ambiguous referent or justify substituting a specifically requested page.

The proposed next step is one **offline planner dependency-context correction**
using the existing schema: retain the exact subject or ordered group together
with the governing requested source context in each dependent query/reference;
choose its source from that interpreted request rather than from the intended-use
label; require clarification when no unique requested referent exists. The app
continues to validate declared literal context, never guess or repair it. The
authored alternatives demonstrate that the existing fields can represent these
corrections; they do not show that another prompt will reliably produce them.
Freeze varied language, negation, page-reference, owner and mixed-purpose
contrasts before candidate edits. Keep successful controls and all remaining
failures visible; do not raise development scores through relabeling or case rules.
Any later live comparison needs its own bounded execution step and budget check.

Retain the unchanged draft requirement to return unknown when available quotes
do not answer the actual target. Actual bilingual draft behavior remains untested;
the structural validator's explicit semantic-unverified flags must remain false.
Do not add a judge, retry loop, keyword/fuzzy router, source inference, larger
budget or index change based on this diagnosis. V9, reserved evaluation and
serving acceptance remain on hold.

Diagnostic evidence is under `artifacts/m5-referent-consumer-diagnosis-v1`:
`mechanical-replay.json`, `consumer-probes.json`, individual primary reviews,
`supplementary-probes.json`, source/metadata packets and preservation receipts.
The runner is [diagnose_referent_failures.py](../scripts/diagnose_referent_failures.py).
It requires the original capture seal and unchanged executed code before replay;
intentionally changed continuity documents retain exact prior copies for audit.
All model outputs, source policies, default graph, API and data remain unchanged.

The fixture harness calls the existing consumer nodes directly with saved plans; it is not a compiled full-graph or live service replay. Clarification-only fixtures also inspect empty-candidate assembly before safe finalization; the normal compiled graph skips retrieval/assembly for such plans. No retriever or draft dependency is called in either route. Recorded node stages describe the diagnostic invocation only.
