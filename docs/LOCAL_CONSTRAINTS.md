# Target-local constraints and inherited context

The opt-in `local_constraints` profile uses
`offline-rag-planner-local-constraints-v11`. It adds one general field
clarification to the unchanged v10 system prompt. Default planning and public
serving remain unchanged; neither v10 nor v11 is adopted.

The [previous comparison](DEPENDENCY_COMPARISON.md) exposed out-of-part
constraint quotations, omitted shared preambles and a fabricated noncontiguous
original quotation. The anchor validator already rejects these representations.
The base prompt did not explicitly state constraint locality. This is a contract
clarity gap, not proof of the model's hidden cause or a measured behavioral fix.

Each `constraint_quotes` item must be an exact unique fragment wholly inside
that part's `original_text`. Inherited source restrictions, prohibitions,
subject/groups and time conditions still matter: carry their necessary literal
context in `reference_text` and each independent public `retrieval_query`, with
additional necessary literal constraints in that query. An empty local list
does not cancel inherited meaning. References and queries do not cover original
request characters; contiguous original spans must cover the complete request,
including shared leading/trailing qualifications, conjunctions and punctuation.
Never fabricate a noncontiguous quotation or copy an independent question into
another original target merely to carry context.

The schema, field limits, literal anchoring, complete coverage, history binding,
source policy, purpose/language/authority metadata and draft instructions are
unchanged. The application does not move, append, drop or repair model text.
Explicit source overrides and genuine ambiguity remain. No new judge, stage,
loop, retry, token guard or source inference was introduced. Trusted offline
construction and the shared screen helper accept this candidate; generic live
CLI allowlists remain unchanged.
